Como usar esta lista

Cada item tem um código (ex.: BTN-01) para vocês referenciarem em conversa ou no board de tarefas. Marque a caixinha ao lado de cada item conforme for implementando — o progresso fica salvo neste navegador. Os itens com a tag 📱 mobile pedem atenção específica na experiência de toque, não só em telas menores.

A prioridade de cada item segue a cor da barra à esquerda: crítico (compromete a credibilidade ou quebra em algum cenário real), alto (é o que mais "resolve" a sensação de inacabado), médio (refinamento perceptível) e baixo (polimento fino). Itens verdes são pontos que já estão bem resolvidos — não mexer.

Ordem de execução sugerida

Se o objetivo é sair rápido do "grosseiro" sem se perder nos 30+ itens, essa é a sequência de maior retorno por esforço.

① Antes de divulgar

  • LAY-01 Trocar todos os placeholders "[PLACEHOLDER — screenshot...]" por prints reais ou mocks estáticos de alta fidelidade.
  • MOB-01 Validar a barra fixa inferior do mobile (sticky CTA) contra o rodapé e o formulário final.
  • FX-02 Confirmar que nenhuma seção fica com título/CTA invisível ao rolar rápido ou ao entrar direto por link com âncora.

② Maior ganho de percepção

  • CARD-01 Sombra sutil em repouso nos cards e nos mockups (o token já existe, só não é usado).
  • BTN-01 / BTN-02 Unificar e reforçar o hover dos botões (lift + sombra em todas as variantes).
  • FX-03 Efeito de destaque nos mockups (float sutil, glow, zoom no hover).
  • FX-04 Indicador ativo no menu (scroll-spy + sublinhado animado).

③ Polimento fino

  • DS-02 / DS-03 Consolidar tokens de azul e usar toda a escala de raio (pills, cantos maiores nos mockups).
  • MOB-03 / MOB-04 Chips com min-height e stepper de 7 passos revisado para mobile.
  • CARD-03 Resolver o card órfão do grid de 5 segmentos.
  • FX-06 Substituir a seta escondida do comparativo por um rótulo textual no mobile.

O que já está bem resolvido (não mexer)

  • Existe um sistema de design tokens completo e bem pensado (cores, espaçamento, raio, sombra, tipografia fluida, duração de transição) — o problema não é falta de sistema, é aplicação inconsistente dele nos componentes.
  • Acessibilidade de teclado já implementada: skip-link, :focus-visible com contorno próprio e anel de foco nos campos de formulário.
  • Contraste de texto validado (cinza dos títulos H2 sobre branco ≈ 7,6:1) — a leitura de "clean" que passa hoje não é acaso.
  • Header, menu mobile (drawer) e empilhamento dos CTAs em coluna no mobile já seguem boas práticas de toque.
  • prefers-reduced-motion já é respeitado nas animações.

Feito a partir de inspeção da página em produção (DOM, CSS computado e tokens do design system) em viewport desktop; os itens de mobile foram derivados das media queries reais do código, já que não foi possível emular um viewport de toque nesta sessão — vale uma conferência visual rápida no responsive mode do navegador antes de fechar os ajustes marcados como 📱.
